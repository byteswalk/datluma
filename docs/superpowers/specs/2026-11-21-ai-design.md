# AI 增强设计

2026-11-21 用户确认按推荐全部做，中途不再确认，做完一起验收。

## 目标

客户接入自己的大模型 API key，或本机已有的智能体命令行，在现有功能上加 AI 辅助。AI 只给建议，不替人执行。

## 数据边界

- 默认只发结构：库、表、字段名、类型、注释、索引、对象定义、报错、执行计划。
- 样例数据只在“补注释”时用，按连接单独打开（连接的“高级”页），生产连接打开时再确认一次。每表最多 5 行，每个值截到 50 个字符。
- AI 生成的 SQL 一律不自动执行：放进编辑器或设计器，由人执行或保存，照常走生产确认（审计版照常走拦截和工单）。
- 审计版由管理员统一配置提供方，用户不能自己填 key；不发样例数据；每次 AI 请求都记审计。

## 提供方

新 crate `dblens-ai`，只管“发一段对话、拿回文本”，不碰数据库。

| 类型 | 说明 |
|---|---|
| `openai` | OpenAI 兼容的 `/chat/completions`。DeepSeek、通义千问、智谱、Kimi、OpenAI、Ollama、vLLM 都用它，界面给常用地址的预设 |
| `anthropic` | Anthropic 的 `/v1/messages` |
| `cli` | 本机智能体命令行的非交互模式，如 `claude -p`、`codex exec -`。提示词从标准输入传入，读标准输出。只在桌面版和只监听本机的服务器版可用（`local_files`），在一个空的临时目录里运行 |

- 不做流式输出：生成 SQL、解释这类回答都短，等待时显示进度并可取消。超时默认 120 秒，可调。
- 走系统代理环境变量（`HTTPS_PROXY`）。
- 配置存在本地库 `settings` 的 `ai.config`（不在 `ui.*` 下，有单独接口）；API key 存在密码库，新表 `app_secrets`（密钥环模式用账号 `app:ai.key`）。

## 接口

- `GET /api/ai/config`：返回配置（不含 key，只有 `has_key`）、`configurable`、可用类型。
- `PUT /api/ai/config`、`PUT /api/ai/key`、`POST /api/ai/test`：只在可配置时开放。
- `POST /api/ai/ask`：`{task, profile_id, schema, sql?, error?, instruction?, plan?, object?, target?, table?, issue?}`，返回 `{text, sql?, comments?}`。上下文由服务端按任务从元数据组装，前端只给“要做什么”，这样数据边界只在一处控制。

任务：

| task | 入口 | 上下文 | 返回 |
|---|---|---|---|
| `generate` | 编辑器“AI 生成 SQL”（Ctrl+I） | 当前模式的表和字段（表多时只给表名，再按问题里提到的表补字段） | SQL 和一句说明 |
| `fix` | 执行出错时结果区的“AI 修复” | 语句、报错、语句里涉及的表结构 | 改好的 SQL 和原因 |
| `explain` | 编辑器右键“AI 解释” | 语句、涉及的表结构 | 中文解释 |
| `optimize` | 编辑器右键“AI 优化建议”、执行计划结果的“AI 分析计划”、单元格查看框的“AI 优化这条 SQL”（运维页慢 SQL 的语句列也走这里） | 语句、执行计划（有就带）、涉及表的索引 | 建议和可选的改写 SQL、建索引语句 |
| `convert` | 结构迁移完成后“未迁移的对象”列表里每项的“AI 转换” | 对象定义、源库和目标库类型 | 目标库的建对象语句，放进目标连接的编辑器 |
| `comments` | 表设计器“AI 补注释”；文档导出的“用 AI 补充缺失的注释” | 表结构（连接允许时加样例） | 表注释和各字段注释，只填空着的 |
| `lint_fix` | 规范检查结果、设计器规范页每条问题的“AI 建议” | 问题、表结构 | 解释和修改语句 |
| `review` | 审计版工单提交后（内部接口） | 语句、规则命中和涉及对象、涉及的表结构 | 给审批人看的摘要 |
| `sensitive` | 审计版管理端“敏感列”（内部接口） | 表名、列名、类型、注释 | 候选敏感列和类别 |

- 设计器补注释只填表单，保存仍走原来的预览、确认流程；库不支持注释时（如 SQLite）不显示。
- 文档导出补的注释只写进文档，不改库，文档里标“（AI 推断）”。每次请求最多 10 张表。

## 界面

- 设置对话框加“AI”页：开关、类型、地址、模型、API key、命令行（只桌面版和只监听本机的服务器版）、超时、“测试”。下面给出 MCP 的配置片段。
- AI 结果统一用一个弹窗：说明文字加 SQL 块，按钮按场景给“插入到编辑器”“替换选中”“在新标签页打开”“复制”。
- 没配置时 AI 菜单项不显示；可配置的版本在设置里提示去配置。
- 风格按现有黑白基调，不加彩色按钮。

## MCP 服务器

新 crate `dblens-mcp`，基于官方 Rust SDK `rmcp`，标准输入输出传输。

- 启动：桌面版 `DBLENS.exe --mcp`（不开窗口），服务器版 `dblens-server mcp`。读同一个数据目录。
- 只暴露连接“高级”页勾了“允许本机智能体通过 MCP 访问”的连接。
- 工具：`list_connections`、`list_schemas`、`list_tables`、`describe_table`、`run_query`。`run_query` 只接受一条只读语句（`policy::classify` 判定为 DQL），最多返回 200 行。
- 密码库模式下有保存密码的连接打不开（命令行没法输主密码），报错说明。

## 审计版

- 配置：`DBLENS_GATE_AI_CONFIG` 指向 JSON（`kind`、`base_url`、`model`、`key_env`、`timeout_secs`、`ticket_summary`），和即时通讯、单点登录一样只走配置文件。控制面启动引擎时把配置和 key 用环境变量交给引擎，引擎里 AI 为“固定配置、不可修改、不发样例”。不支持命令行类型。
- 路由：放开 `GET /api/ai/config`、`POST /api/ai/ask`，其他 AI 接口不开放。控制面转发 `ask` 前记审计 `ai_ask`（连接、任务、语句、问题前 200 字）。
- 审批摘要：配置了 `ticket_summary` 时，提单后控制面请引擎生成摘要（做什么、涉及哪些表、风险在哪），最多等 30 秒，存进工单，再发待审批通知。工单详情和即时通讯卡片显示“AI 摘要（仅供参考）”。审计 `ticket_ai_summary`。判定仍按规则。
- 敏感字段：管理端新页“敏感字段”（安全管理员）。选连接和模式点“AI 识别”，只发表名、字段名、类型、注释，返回候选（字段、类别、理由）；管理员勾选确认后保存，审计 `sensitive_save`。效果：工单详情和卡片列出所涉及表里的敏感字段，提醒审批人。不做脱敏，和现有定位一致。
- 迁移 `V14`：`dg_tickets.ai_summary`、`dg_sensitive_columns`。

## 不做

流式输出、多轮对话、AI 自动执行、在库里自动改注释、审计版里的命令行提供方、脱敏。

## 验收

- 单元测试：各提供方的请求和响应（本地假服务器）、上下文组装的边界（不带样例、截断）、命令行提供方、MCP 只读拦截。
- 真实模型：用本机能用的提供方实测各入口（有哪个用哪个，记在笔记里）。
- 界面用真实鼠标走一遍每个入口。

## 实现记录（2026-11-21）

- 回答不流式；弹窗里文字和代码块分开显示，只认标题、粗体、行内代码、分隔线，不解析 HTML。
- 小模型常忽略系统提示里的语言要求，问题末尾再说一次“用某语言回答”。
- 发给模型的版本号还原成 `主.次.补丁`（内部编码是 `major*10000+minor*100+patch`）。
- 读样例数据、MCP 查询都在新连接上执行，先过执行策略（审计版据此判定和留痕），在事务里读完回滚。MCP 查询只接受一条只读语句，`SELECT … INTO` 也拒绝。
- 审计版的 `ai_ask` 审计记任务、连接、模式和语句或问题的前 200 字；工单摘要由引擎内部接口生成，连接取控制面的快照，不按操作者过滤。
- 实测：本机 Ollama `qwen3:8b` 跑通 9 项任务（单次 6～55 秒）；命令行提供方用 `codex exec --skip-git-repo-check -` 跑通连通测试。界面用真实鼠标走过：设置页测试、生成 SQL 并插入执行、报错修复并替换原语句、右键优化建议、执行计划分析、单元格 SQL 优化、设计器规范页建议、文档导出补注释、迁移对象转换并在目标连接打开、连接高级选项和生产确认。
- macOS（Mac mini M6，arm64）上的桌面版用真实点击走过：设置 AI 页填写并测试、新建 SQLite 连接、Cmd+I 生成并执行、右键 AI 解释、报错后 AI 修复并替换原语句。实测中补了两处：语句里的表名一个都对不上时把模式里的表名发给模型（否则写错表名修不对）；回答语言写明简体，避免模型改用繁体。
